# LexHelper 桌面界面设计

## 目标与单文档例外

Windows 10/11 x64、Unicode Win32 标准控件。用户打开一套新世纪码表，检查完整记录的虚拟预览，再另存 lex 或明确确认系统安装。采用**单文档**：一次只允许安装一套完整码表，避免多标签的“活动文档”与待安装来源不一致。导入成功标为未另存；重新打开或退出均提供“另存为新 lex / 放弃 / 取消”。安装不自动清除未另存标记。导入失败保留先前码表，不部分替换。

## 信息架构与布局

1. 原生系统标题栏：菜单、系统菜单、拖动、贴靠、最小化、最大化、关闭全部交给 Windows；菜单为文件、系统、帮助。单文档例外不设置 Tab，不自绘非客户区。
2. 系统状态与工具区：只查询 `system_lex_directory()` 下的 `ChsWubi.lex`、`ChsWubiNew.lex` 是否存在及大小，不读取解析整个系统词库；系统路径为可复制只读编辑框。打开、另存、备份、安装、恢复、刷新按钮与菜单同源；下一行放管理员重开及权限说明。
3. 内容区：来源、未另存状态、记录数、单 Unicode 字符记录数、各码长记录数；原生 report ListView 展示编码、词条、导入后模型的 lex weight（代价，越小越靠前）。列标题为“权重（小值优先）”，不是搜狗原始词频；帮助明确解释该区别。WBC3 候选顺序和文本频次转换为代价，lex 输入保留所支持的 weight。`LVS_OWNERDATA` 按需向模型取值，不向控件插入 70,870 个项目。无异步排序或筛选；不会隐藏部分词条冒充全部导入。
4. 底部：带标签的可复制只读日志，显示成功、完整异常、生成路径、备份/恢复路径；标准状态栏显示忙碌、安全退出及成功/失败。日志仅保留有限界面文本，较旧内容有明确移除标记；不宣称为磁盘审计日志。

最小客户区 840 × 570 DIP，默认 1080 × 760 DIP，并按主显示器工作区收缩、居中。列表随窗口伸缩，底部日志优先保留 88 DIP；主操作不藏入溢出菜单。极小屏幕或超大文本缩放超出最小设计宽度时可能需要更大可用桌面，须人工验收。

## 导入、保存与系统操作

- 标准 `IFileOpenDialog` 支持 CWB / WBC3 / 文本 / lex。标题、筛选和按钮提示明确 CWB **只选 WBC3 新世纪**，不混入 WBC1/2；实际格式、完整错误和支持版本由核心解析器裁定。未知搜狗元数据不冒称完整保留。
- 标准 `IFileSaveDialog` 标注“选择不存在的新文件，不覆盖”；关闭系统覆盖询问，核心 `save_lex` 原子地拒绝既有文件，包括输入文件。失败保留当前模型与未另存状态；另存成功后才能执行等待中的打开/退出动作。
- manifest 为 `asInvoker`。普通权限下可导入和另存；备份/安装/恢复入口要求管理员。原生 UAC `ShellExecuteEx(runas)` 仅打开同一可执行文件，**无自动部署参数**。当前窗口保留；新管理员窗口需重新导入并再次点击、确认操作。取消 UAC 不影响当前结果。
- 系统状态查询失败时禁用系统操作，刷新后再尝试。实际部署一律 `system_mode=true`，目标、备份根目录仅由部署 API 得到，不接收用户任意系统目标路径。
- 安装和恢复均采用警告 TaskDialog，取消为默认按钮，只有明确点击安装/恢复按钮才开始后台操作。安装显示来源、类型、记录数、系统目标和备份根目录；恢复显示所选备份目录和系统目标。两者均说明：仅在有系统级恢复途径的可恢复环境操作、不保证所有 Windows 或输入法兼容、完成后需注销并重新登录、不强杀进程/停止服务。安装另提示 Windows 更新可能覆盖结果。
- 部署通过新对象替换 CHS 目录项，不原位改写其他硬链接指向的原实体。确认中明确恢复的是内容、存在性及完整安全属性，**不恢复硬链接关系或文件 ID**；失败仅尽力回滚，不保证跨文件、断电或进程崩溃原子性。无法安全读取/恢复安全属性时拒绝，不引导用户放宽系统 ACL。完整边界以 [部署与权限说明](部署与权限说明.md) 为准。
- 每次安装在 `%LOCALAPPDATA%\LexHelper\Generated\{新 GUID}\ChsWubi.lex` 创建唯一制品。创建前逐级打开并固定所有祖先目录，拒绝目录联接/符号链接；全过程持有不共享删除的目录句柄。核心另存后独立读回、比对当前来源的生成字节、记录数及规范化重新序列化结果；制品读句柄不共享写入/删除，一直持有到部署结束，防止校验后被替换。目录不复用，既有文件不覆盖；保留本次制品用于故障诊断，路径写日志。重定向到重解析点的用户数据路径会保守拒绝安装。应用自身用户数据不是 AI 测试临时区，自动烟测不会安装或创建这些制品。
- 手工备份每次创建独立目录；manifest schema v2 / FSD2 保存内容、存在性、Owner/Group/DACL/审计 SACL/完整性 label 及保护/继承控制位。恢复使用标准目录选择器，仅交由部署器验证自身备份 schema；拒绝旧 v1、损坏备份和无法匹配的当前状态，不把任意 lex 当备份。恢复无需导入码表，提交前另建当前状态恢复点。失败同时显示真实异常、所选恢复目录/备份根目录及已生成制品路径，不虚称已完整回滚。成功展示可复制的恢复路径并提示注销/登录；不结束 ctfmon、不停止服务、不强行刷新输入法。

## 线程与资源生命周期

全部解析、统计、生成、文件查询、备份、安装、恢复都在单个 `std::jthread` 中串行执行。UI 仅操作原生对话框和模型快照；忙碌时禁用可重入命令，但窗口仍能响应绘制、移动、调整尺寸、查看已有日志。

后台结果由 `unique_ptr<Result>` 持有，受互斥保护放入 Application 的完成槽；`PostMessage` **不传裸指针**，100ms UI 定时器作为通知投递失败的取回机制。线程捕获的 Application/目标 HWND 仅在窗口明确保持存活的期间使用。关闭时若忙碌，记录待退出请求，等待当前任务安全结束；这一等待规则适用于导入、保存、查询和部署，并非只有系统事务不能中断。完成后先 join，再做未保存确认，最后 DestroyWindow。没有 detach、强杀线程或运行中取消按钮；取消只发生在启动前的对话框安全边界。异常不跨越线程入口或 WndProc。

主线程 STA COM、工作线程 MTA COM 均成对释放；COM 接口、任务内存、进程/令牌 HANDLE、线程、字体均明确所有权。字体重建先把新字体设置到所有子控件和列表表头，再释放旧字体；借用的系统图标、光标、画刷、默认字体不释放。主窗口拥有菜单，销毁时由系统处理。

## 键盘、主题、DPI 与可访问性

- Ctrl+O 打开，Ctrl+S 另存，Alt+F4 请求退出；菜单显示快捷键。Alt 菜单和按钮助记符、Tab/Shift+Tab 由 `IsDialogMessage` 及原生控件导航实现；列表使用标准方向键/滚动，原生对话框负责模态焦点。
- 控件使用可读中文按钮文本、列表列标题、路径和日志标签；不以颜色作为唯一反馈，忙碌/未另存/失败均有文字。只读路径、日志保留 Tab 焦点以便复制；空状态明确，并禁用保存和安装。
- 使用系统字体和 `COLOR_BTNFACE` 等语义颜色，标准控件服从系统主题/高对比度；不依赖固定品牌颜色或非公开深色 API。完整自绘深色外观不在本轮范围，系统深色设置下允许保留系统支持的原生浅色控件；高对比度优先。
- manifest 声明 `PerMonitorV2`；`WM_DPICHANGED` 按建议边界调整、重建系统 DPI 字体、重排布局；最小尺寸通过 `AdjustWindowRectExForDpi` 计算。`WM_SETTINGCHANGE/WM_THEMECHANGED` 重建字体与重绘。没有动画，不需要额外减少动态效果开关。

## 构建接入

- GUI 源：`src/gui/main.cpp`；资源：`resources/app.rc`（通过相对资源路径嵌入 `app.manifest`）。应用目标必须为 `WIN32`，入口 `wWinMain`，Unicode、`/utf-8`、C++23。
- include 路径支持 `lexhelper/core.hpp`、`lexhelper/deploy.hpp`（同时兼容裸 `core.hpp/deploy.hpp` 契约路径）。链接 `lexhelper_core`、`lexhelper_deploy`。
- Win32 直接链接库：`comctl32`、`ole32`、`shell32`、`advapi32`、`user32`、`gdi32`、`uuid`。其他依赖由核心/部署 target 自身传递。
- **manifest 只能有一个来源**：本资源已经嵌入清单。MSVC/CMake 若仍生成默认清单，需要为 GUI target 设置 `/MANIFEST:NO`（或改为仅 `/MANIFESTINPUT` 并去掉 rc 清单；二选一，不可同时嵌入两份）。GUI 子任务不修改根 CMake，由父流程整合。
