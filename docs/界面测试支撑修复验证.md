## 根因与改变

### GUI-002：恢复认证不是原实例身份

旧脚本只保存 suite 开始时间，恢复构造函数又从当前 PID 读取时间作为自己的比较基准。PID 被同 EXE 新实例重用时，时间下界不能认证原实例。

现在从 **CreateProcess 返回且持续持有的原始进程句柄**取得创建时间，用字符串 `CreationTimeUtcTicks` 保存完整 100 ns UTC ticks，另有 `CreationTimeUtc` 的 `o` 格式显示值；同时保存 PID、EXE。启动后、窗口等待前即写 `process-<PID>-<ticks>.json`。恢复必须提供同一条原始记录的 EXE、PID、ticks，OpenProcess 后精确比对，再允许任何窗口枚举/消息；旧 `TaskStarted`/无精确时间记录拒绝自动处理。`StartedAt` 仅供报告，不授权清理。

### GUI-003：创建成功、窗口初始化失败丢失所有权

构造函数不再等待窗口；调用顺序为：获得 Session → 持久记录原身份 → `InitializeWindow()` → 业务检查。因此 input-idle/主窗口/Ready 验证失败时 finally 仍持有原 Session。

`OwnedProcess` 用 SafeProcessHandle 持有 CreateProcess/OpenProcess 原句柄，通过该句柄等待退出和查询退出码，避免后续按 PID 重找实例。Dispose 只释放句柄，**不等于结束进程**。捕获身份失败也保留 PID 和具体 CaptureError；不完整身份不能发送清理消息。

`CloseNormally` 使用有限时间预算、已认证原实例和窗口白名单正常关闭；未知窗口不碰。遗留/无法确认状态返回非空的 `CleanupResult`，含原始 `Identity`、`State`、`Reason`，不是把 PID 写成 null。回归/烟测保留此结果并非零退出；句柄释放置于 finally。启动错误窗口可正常关闭，只有明确交互测试/恢复选项才允许处理已知 fixture 的文件/未保存对话框。枚举回调内异常先捕获，返回托管代码后再抛出。

### GUI-004：能力探测 catch 吞掉业务断言

现在 C# 返回分字段能力结果，PowerShell 在探测之后单独断言，业务断言周围没有转成 NOT EXECUTED 的 catch。可读权重标题须精确等于“权重（小值优先）”；支持读取 Unicode 值时，必需值须精确匹配，错误进入 suite FAIL/非零退出。只有明确不支持接口/操作或没有 provider 才跳过；E_FAIL、权限/RPC/其他错误不伪装为能力缺失。

accValue 保留原 HRESULT：`S_FALSE`/明确不支持属性可表示该字段能力缺失；**S_OK 返回空串/null 也必须保留为有效返回后的错误值，不能按“非空内容”推断能力**。自测覆盖可读空值 FAIL。只将确实未提供的 **Unicode 子列**列为未完成，不能掩盖已可读标题错误。依据：[Microsoft 的返回值检查说明](https://learn.microsoft.com/en-us/windows/win32/winauto/checking-iaccessible-return-values)、[get_accValue 契约](https://learn.microsoft.com/en-us/windows/win32/api/oleacc/nf-oleacc-iaccessible-get_accvalue)；[ListView 文档](https://learn.microsoft.com/en-us/windows/win32/winauto/list-view-control)也明确回调型条目文本的 MSAA 局限。本次共享函数 fixture 验证分类，另用真实程序**空预览**验证原生 COM/header 查询；没有宣称载入后的 Unicode 子列已集成通过。

### GUI-005：计时覆盖与产品结果混淆

150,000 行样本保持原大小，一次有界尝试，无新增固定 sleep/盲目扩容/导入重试。未赶上 busy 时只记录该项 NOT EXECUTED；仍须在有界等待内验证正常导入的条数和 dirty 状态，不把失败导入藏进跳过。确实观察 busy 后，禁用命令、延后关闭日志、正常退出仍是硬断言，错误必须 FAIL。报告增加 UTC 检查点、尝试上限和 `SkippedCount`；覆盖未获得不是 busy-close PASS。

### GUI-001：预留真实产品断言，未减弱

烟测与回归首次 Ready 后都只读检查按钮及菜单：备份 1102/恢复 1104 启用；空表保存 1002/安装 1103 禁用。没有点击这些系统命令。支撑自测另用命令调用即抛错的假对象验证该断言及错误状态退出码。随后父流程完成 GUI-001/CORE-001 整合构建并提供新制品，本阶段追加只读实测，两配置首次 Ready 状态均通过；最终独立完整测试仍由父流程另派。

## 复现命令

在仓库根目录用 PowerShell 7 运行，仅编译/启动自建 fixture，不需要产品 EXE：

```powershell
$root = Join-Path 'D:\temp\aiRunner\opencode' ('LexHelper-fix-guitools-' + (Get-Date -Format yyyyMMddHHmmss) + '-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $root | Out-Null
pwsh.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tests\gui_support_selftest.ps1 -TemporaryDirectory $root
# 预期 exit 0、PassCount=31；故意失败的子进程退出 1 是自测的必要断言。
```

后续仅对**自己启动且记录完整**的原实例恢复（不要用旧 suite 开始时间，也不要针对手动实例补写身份）：

```powershell
$record = Get-Content -LiteralPath '<单个原始 process-PID-ticks.json 的路径>' -Raw | ConvertFrom-Json
$i = $record.Identity
if (-not $i.CreationTimeUtcTicks -or $i.CaptureError) { throw '记录不完整，拒绝自动恢复' }
pwsh.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tests\gui_cleanup.ps1 `
    -Executable $i.Executable -TemporaryDirectory '<该次测试的临时目录>' `
    -RecordedProcessId $i.ProcessId -RecordedCreationTimeUtcTicks $i.CreationTimeUtcTicks
# 默认不处理未保存/文件对话框；确为交互 fixture 时才显式加 -AllowKnownFixtureDialogs。
```

只读产品检查使用已核对 SHA256 的制品，示例（目录须先创建）：

```powershell
pwsh.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tests\gui_smoke.ps1 -Executable .\out\vs2026\Debug\LexHelper.exe -TemporaryDirectory "$root\product-smoke"
```
