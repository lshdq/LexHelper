# 完整安全属性读取修复：开发证据与未验证边界

日期：2026-11-18。父 dev-workflow 阶段 5；这不是独立测试/审查或真实安装验收。

## 结论先行

- 用户的 `GetSecurityInfo(BACKUP_SECURITY_INFORMATION)` 返回 5 是真实故障；**现有证据不足以确认其管理员现场根因**。没有访问真实系统 lex，没有 UAC、真实备份/安装/恢复、改系统 ACL、改账户权限或停止服务。
- 本机普通令牌无 SeSecurity/SeBackup/SeRestore。自建 D 盘文件实测：请求 ACCESS_SYSTEM_SECURITY 在 **NtCreateFile 阶段**返回 `0xC0000061/1314`，无论是否 backup intent；只打开 READ_CONTROL 后普通查询成功，显式完整查询和 BACKUP 查询均返回 5。此结果不能冒充“管理员已经开出完整权限句柄但 BACKUP 查询失败”的复现。
- 修复是**有界、完整性不降级的兼容性补救及可定位诊断**：检查实际 GrantedAccess；保留 GetSecurityInfo 主路径，在其返回 5/1314 且句柄确有完整权限时，仅再用同句柄、同 BACKUP 标志的 NtQuerySecurityObject 查询一次。成功结果仍经过原 schema 验证；两个 API 都失败则拒绝且保留两个错误。没有凭猜测增加 SeBackup/SeSecurity 查询期重试。
- 管理员成功分支（包括此兼容路径是否解决用户现场问题）**未验**；不能对外承诺“已确认 SeBackup 时序根因”或“真实系统安装已修复”。应先完成后续独立门禁和授权的管理员临时文件验证。

## 1. 基线、真实调用链与根因证据

本轮起点是 `.localdoc/审查记录/基线-完整安全属性读取修复-20261118092336/files/`，不是新项目。未提交 main 的既有 47 文件均保留。旧 `tests/deploy_tests.cpp`、CMake、GUI、核心和公开头文件未改。

原调用链：`backup/install/restore -> Context -> Files -> open_regular -> snapshot -> get_full_security`。其他完整读取还发生于暂存制品应用安全属性前后、准备校验、提交后校验及回滚校验；它们可用同一个逻辑 `ChsWubi.lex` 路径报错。因此没有完整日志不能仅凭旧错误路径断言用户前次尝试绝对未改文件。

静态核查事实：

1. 原 `open_regular` 给非模拟的 controlled_target 显式加 ACCESS_SYSTEM_SECURITY；相对 NtCreateFile 一直使用 FILE_OPEN_FOR_BACKUP_INTENT。打开失败 5/1314 才尝试私有线程令牌的 SeSecurity，其他所需 Backup/Restore 也只在相关访问失败后启用。普通成功后直接查询，不存在一个已确认的“必然漏开 SeBackup”结论。
2. Privileges 属于 Context，寿命长于文件句柄/快照；正常及异常退出恢复原线程令牌。get_full_security 原来没有改变/关闭它。若因 SeSecurity 打开失败重试获得句柄，该私有令牌仍活着。
3. 元数据句柄还会通过 `controlled_target=false` 但显式 ACCESS_SYSTEM_SECURITY 的路径打开；旧的 SeSecurity 打开失败重试仅看 controlled_target。现统一看实际请求的 ACCESS_SYSTEM_SECURITY。这是局部一致性修正，并非已证明的用户原始报错根因。
4. 缺少用户现场的 GrantedAccess、有效线程 token 和各次查询结果，无法区分完整权限句柄上的 Win32 API 路径差异、环境拦截/策略或其他原因。没有把其他操作系统实现、搜索到的第三方案例或推断当作 Windows 实机证明。

## 2. 官方依据（本轮在线核验）

| 资料 | 可核验结论与边界 |

| [SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information) | BACKUP 表示所有分量，查询权是 READ_CONTROL + ACCESS_SYSTEM_SECURITY；不能改为仅五个显式常见分量后还宣称与 BACKUP 完全等价。 |

| [QuerySecurityAccessMask](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-querysecurityaccessmask) | 用于核对请求对应的访问权；本机 0x1F、0x10000、0x1001F 的实际结果都是 0x01020000。 |
| [NtCreateFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile) | backup intent 影响打开时的权限检查；RootDirectory 绑定对象相对名。这个 create option 不等于 BACKUP_SECURITY_INFORMATION，也不等于已取得所有请求权限。 |
| [Privilege Constants](https://learn.microsoft.com/en-us/windows/win32/secauthz/privilege-constants) | Backup/Restore 在备份/恢复语义下能授予部分访问权（包括 ACCESS_SYSTEM_SECURITY）；不是 GetSecurityInfo(BACKUP) 查询必须另开 SeBackup 的证明。 |
| [NtQueryObject](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntqueryobject) | ObjectBasicInformation 的公开结构提供 GrantedAccess；动态绑定，缺少/失败安全拒绝。这是 Native 接口，微软保留后续变更可能性。 |
| [ZwQuerySecurityObject / 用户态 NtQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwquerysecurityobject) | 同句柄返回 self-relative SD；文档要求用户态使用 Nt 名称；NTFS 描述符上限 64 KiB。Native 页的分量表较旧，BACKUP 含义仍按上面的 SECURITY_INFORMATION 官方表，不把旧表缺项解释为允许截断。 |

## 3. 实质选项与本轮选择（交父流程登记唯一决策）

| 选项 | 权衡 |
| --- | --- |
| 仅加诊断，等待已提升样本再改读取 | 最保守，不改变成功路径；用户同类 API 路径问题仍必然失败。可作为管理员验证仍不足时的交付边界。 |
| **检查实际句柄权限，GetSecurityInfo 权限失败后一次同 BACKUP 原生查询** | 本轮选择。保留原主路径，只绕过可能有差异的 Win32 查询封装，不绕过对象授权；仍向内核请求完整 SD。新增 Native API 依赖与未验成功分支，必须如实披露。 |
| 一律改用 Native 查询 | 更短，但所有已有原生成功路径都换 API，回归面较大；本轮不用。 |
| 查询失败后启用 Backup/Security 再试 | 无证据证明必要；已打开句柄缺权不能这样修复，且与 GetSecurityInfo 官方时序说明不符，不采用。 |
| 去掉 BACKUP，拼 Owner/Group/DACL/SACL/label | 可能漏掉 BACKUP 包含但显式投影未要求的安全信息，也会掩盖原错误，拒绝。 |

不引入 DACL-only、NULL-SACL 容错、按路径重开、takeown、ACL 放宽、修改 process token 或不受限重试。若管理员验证显示两条完整查询都失败，保持拒绝并用新增诊断定位，不继续猜测加特权。

```cpp
#define WIN32_LEAN_AND_MEAN
#define NOMINMAX
#include <windows.h>
#include <winternl.h>
#include <aclapi.h>
#include <filesystem>
#include <cstdio>
#include <vector>

#pragma comment(lib, "advapi32.lib")
struct Handle {
    HANDLE h{INVALID_HANDLE_VALUE};
    explicit Handle(HANDLE v) : h(v) {}
    ~Handle() { if (h && h != INVALID_HANDLE_VALUE) CloseHandle(h); }
};
void privileges() {
    HANDLE raw{};
    bool thread = OpenThreadToken(GetCurrentThread(), TOKEN_QUERY, TRUE, &raw) != FALSE;
    if (!thread && !OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY, &raw)) return;
    Handle t(raw);
    const wchar_t* names[]{SE_SECURITY_NAME, SE_BACKUP_NAME, SE_RESTORE_NAME};
    DWORD n{}; GetTokenInformation(t.h, TokenPrivileges, nullptr, 0, &n);
    std::vector<unsigned char> b(n);
    if (!GetTokenInformation(t.h, TokenPrivileges, b.data(), n, &n)) return;
    auto p = reinterpret_cast<TOKEN_PRIVILEGES*>(b.data());
    std::printf("effective_token=%s", thread ? "thread" : "process");
    for (auto name : names) {
        LUID id{}; LookupPrivilegeValueW(nullptr, name, &id);
        const char* state = "absent";
        for (DWORD i=0; i<p->PrivilegeCount; ++i)
            if (p->Privileges[i].Luid.HighPart == id.HighPart && p->Privileges[i].Luid.LowPart == id.LowPart)
                state = (p->Privileges[i].Attributes & SE_PRIVILEGE_ENABLED) ? "enabled" : "disabled";
        std::printf(" %ls=%s", name, state);
    }
    std::puts("");
}
void queries(HANDLE h) {
    const auto q = reinterpret_cast<decltype(&NtQueryObject)>(GetProcAddress(GetModuleHandleW(L"ntdll.dll"), "NtQueryObject"));
    PUBLIC_OBJECT_BASIC_INFORMATION info{}; ULONG length{};
    auto s = q(h, ObjectBasicInformation, &info, sizeof(info), &length);
```
