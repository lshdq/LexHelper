## 2. 官方依据与本机声明核验

2026-11-17 只读交叉核验：

1. [NtCreateFile（winternl.h）](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile)：`OBJECT_ATTRIBUTES.RootDirectory` 非空时名字相对该目录；`FILE_CREATE` 在已有对象时失败而非打开/覆盖；`FILE_OPEN_REPARSE_POINT` 绕过目标的正常重解析处理；同步 NONALERT 选项要求 `SYNCHRONIZE`。
2. [OBJECT_ATTRIBUTES](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes)：RootDirectory 可指文件系统目录；`OBJ_DONT_REPARSE` 不跟随解析中遇到的重解析点，文档给出的失败为 `STATUS_REPARSE_POINT_ENCOUNTERED`。它不是目录元数据锁，不保证与所有其他重解析失败情形返回同一个状态。
3. [RtlNtStatusToDosError](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-rtlntstatustodoserror)：由返回 NTSTATUS 转换，不读取无关的 GetLastError；未映射状态返回 `ERROR_MR_MID_NOT_FOUND`，因此错误同时保留原始 NTSTATUS 数值。
4. [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)：共享标志不能作为排斥所有属性访问的机制。没有用收紧共享代替身份绑定。

本机 SDK `C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um\winternl.h`：475–487 行有 `NTAPI NtCreateFile` 完整声明，636 行有状态转换声明；976/982 行有 `OBJ_CASE_INSENSITIVE/OBJ_DONT_REPARSE`；990–1044 行提供全部使用的 `FILE_OPEN/CREATE`、目录/非目录、同步、重解析及 `FILE_CREATED` 常量。没有手写函数 ABI、魔数旗标或安装 WDK。SDK 的“尽量使用 CreateFile”注释未被忽略：Win32 全路径 CreateFile 不提供此处所需的目录对象相对创建，Native 调用仅封装在本 IO 实现内。

通过已加载的系统 `ntdll.dll` 的借用句柄和 `GetProcAddress` 解析上述两函数，逐项检查失败；不搜索输出目录，不添加第三方库或修改 CMake。不支持时抛错，**不回退到全路径创建**。Release 探针的 `dumpbin /imports` 确认使用 GetModuleHandleW/GetProcAddress，无 NtCreateFile/RtlNtStatusToDosError 静态导入；所需 Win32 导入正常存在。

## 3. 机制、异常与权衡

### 身份不变量

1. 内存编译先完成；路径校验先检查原始文本，再绝对化/词法规范化，之后才绑定对象。原始 `.`、`..` 可规范化，但其邻接组件中的非法字符、ADS、尾空格/点不能因规范化被消除后通过。规范化后的每个组件继续检查设备保留名。
2. 原始设备命名空间检查兼容 `/`、`\` 混合分隔符；显式拒绝 0–31 控制字符，避免改用 Native 后放行 Win32 非法名字。NUL 全路径拒绝。没有扩大允许的设备/流/名字类型。
3. 只从名字打开一次盘符根；UNC 从共享根打开，不把 `\\server\` 误当可打开的共享目录。根也验证为无重解析点的磁盘目录。随后名字均为**单个组件**；禁止分隔符、冒号、空名、`.`、`..`，并在转为 UNICODE_STRING 的 USHORT 字节长前检查范围。
4. 每次目录 `FILE_OPEN` 都带 `OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE`、`FILE_OPEN_REPARSE_POINT | FILE_DIRECTORY_FILE | FILE_SYNCHRONOUS_IO_NONALERT`，并检查已拥有句柄的磁盘类型和目录/重解析属性。保存保留所有目录句柄，但不声称冻结目录名字或属性。
5. 最终 `FILE_CREATE | FILE_NON_DIRECTORY_FILE` 相对已验证父句柄；仍带拒绝重解析/同步选项，share=0。检查 NTSTATUS、有效句柄、`FILE_CREATED`、磁盘类型与普通文件属性后才写入。打开目录所需权限是 TRAVERSE/READ_ATTRIBUTES/SYNCHRONIZE，无需 LIST_DIRECTORY、管理员或修改 ACL。
6. 目录原地改为 junction 时，相对它继续解析可失败；失败是合法安全结果，不需要把它“修复回普通目录”后重试。改名/替换目录名字不会使已有父句柄变成新目录句柄。
7. 所有句柄 RAII；返回的同步打开状态使用 NT_SUCCESS 规则（非负），不请求提前完成/异步 oplock 选项。Native 失败用其 NTSTATUS 转换；Win32 失败即时取错误。写入、零进展、flush、类型/属性检查失败后，**仅在 FILE_CREATED 确认时**按拥有句柄标记删除，绝不用竞争中的路径删除。若删除失败，报告错误并嵌套原始异常，不返回成功。未知创建结果不修改/删除未知对象。

### 明确权衡/支持边界

- 保留普通绝对/相对路径、中文路径、不覆盖和并发单赢家。UNC 语法未主动禁用，但网络/非 NTFS 未实测；系统/文件系统不支持相关操作时安全失败，禁止弱化回退。
- 根目录现在也被检查；无法取得根/各级目录所需属性和遍历权限的受限环境可能比旧实现更早失败。这是身份链必须的 fail-closed 条件，不隐瞒为完全无行为差异。设备前缀混合分隔符、控制字符被明确校验，也是安全收紧。
- Share=READ|WRITE|DELETE 允许目录变化；安全不依赖共享阻止修改。它并非长期锁，也不对抗同权限主体在完成之后再次修改/移动输出。断电/进程被杀仍非事务。
- 采用内部**显式逐调用**回调而非环境变量、全局注册或调度碰运气：生产 `save_lex` 固定传空回调；测试入口与它共用同一个 save_impl。回调在所有父对象已验证、新建前同步执行，无保存到全局/跨线程状态，不暴露可被关闭的目录句柄；回调自身同步由测试负责。独立测试可 `#include "../src/core/io_test.hpp"`，无需项目 CMake 改动。稳定的检查后竞态比仅靠压力线程更有证明力，增加的维护面限于一个内部声明与一个参数化调用点。
