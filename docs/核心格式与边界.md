# 核心格式与边界

## 文件入口的类型判定

`import_file` 只读输入，扩展名仅按 ASCII 大小写不敏感比较（`.TxT`、`.CwB` 等等价），依次选择一次解析器，不捕获二进制解析失败后回退文本：

1. 显式 `.txt/.tsv` 始终按文本读取（规范 TAB 或下述明确标记的多候选方言），UTF-8 BOM 可选；`PK`、`WBC1/2/3`、`imscwubi` 都可作为合法 TAB 词条，不要求中文。真实二进制改名为文本仍须通过严格 Unicode、控制字符、逐行及重复项校验，否则整份拒绝。
2. 显式 `.cwb/.lex/.wbc3` 分别固定 CWB/lex/WBC3 解析器；扩展名与内容 magic 冲突、头损坏或不支持版本直接拒绝，即使带文本 BOM 也不换类型。WBC1/2 不能冒充 `.wbc3` 导入。
3. 其他扩展（包括 `.bin/.wbc`）及无扩展：UTF-8/UTF-16 BOM 明确走文本（UTF-16BE 仍由文本解析器拒绝）；完整四字节 ZIP 标记 `50 4B 03 04`、`50 4B 05 06`、`50 4B 07 08` 走 CWB，后两种并不表示支持空备份或分卷，仍须通过现有 ZIP 校验。
4. 未知类型的可打印 lex/WBC magic 不能单独抢占合法文本：若全文件含 TAB 且没有小于 0x20 的字节（TAB/CR/LF 除外），交给严格文本解析器。这仅是文本包络，不代表 UTF-8 或行格式已合法；非法 Unicode、坏行仍整份拒绝。否则按 `imscwubi`/`WBC3` 选二进制解析器，`WBC1/2` 明确拒绝。真实受支持 lex/WBC 的二进制头含 NUL，不会命中文本包络；截断/损坏输入没有失败回退。
5. 其余内容仍尝试规范文本，不缩窄普通未知/无扩展文本能力。ASCII 魔数碰撞文本因此也能无 BOM 导入。未知类型若已完全变成合法规范文本，无法推断其历史是否曾为二进制；需要强制类型时应使用显式二进制扩展。文件改名不用于绕过任何内容校验。

每次成功的 `ImportResult.source` 对应实际使用的解析器/文本方言，不由扩展名单独生成，并报告全表 GB2312 常用单字→词组→其他单字；多候选文本始终报告已排除动态项行数（包括 0）。GUI 沿用既有来源显示与导入日志，无额外隐藏警告通道。文件类型判定优先级未放宽，不支持任意 Rime YAML。

## 文本

两种方言都只支持 UTF-8（可 BOM）和带 BOM 的 UTF-16LE，非法 Unicode、控制字符、空词条、同码同词重复及超限整份拒绝，不静默跳过坏行；原输入只读。编码须为 1–4 个 a–z。空行或第一个字符是 `#` 的注释可用（不是行尾注释）。

- 规范 TAB：每行两列 `编码<TAB>词条` 或反向，可有第三列 uint64 非负十进制频次；全文件方向/列数必须一致，拒绝编码列歧义。同码先按频次降序、等频稳定行序（无频次按行序）。词条可以包含普通空格；不尝试在错误后猜测其他方言。
- 孤狐多候选：第一个非空非注释行须为 `name=非空表名`（不含 TAB），随后只能是唯一的 `[data]` 段标记（可间隔空行/注释）。段内每行是编码及一个或多个候选，ASCII 空格/TAB 可混用、重复作为分隔，允许尾部分隔、不允许缩进或空编码。候选内不表示空格或 TAB，按同码从上到下、从左到右建立先验顺序。无频次列；数字也是字面候选，不根据内容猜列含义。重复 name/data、其他段/元数据或混入反向 TAB 结构均拒绝。规范 TAB 中 `name=literal<TAB>a` 仍是普通合法词条，不被选择器抢占。
- 动态项仅当分隔后的整行字段恰为 `minute / ^$mi分 / ^$MI分`、`month / ^$m月 / ^$M月`、`second / ^$s秒 / ^$S秒` 才排除并累计行数；不展开宏、不扩大为“跳过所有长编码”。这些长编码的未知/缺失/额外字段、大小写变化等仍拒绝；排除后无正常候选也拒绝。普通短编码的合法词条按字面保留，包括文本中出现的 `^$`，不执行或过滤它们。

公开 `read_text` 签名不变，返回方言先验次序对应的从 1 开始同码排名；内部解析结果额外提供真实方言与排除数，供 `import_file` 来源/日志使用。

## 文件导入权重策略

所有 `import_file` 入口（TXT/TSV、多候选文本、CWB、独立 WBC3、lex）统一为三类：GB2312 常用单字→词组→其他单字。常用单字严格为 GB2312 一级 3755 + 二级 3008 个汉字，固定内置[精确字表](GB2312汉字表来源与生成.md)，不含 GB2312 非汉字符号，也不扩大到 GBK。单字是恰好一个合法 Unicode 标量值；GBK 额外汉字、合法 UTF-16 代理对表示的补充平面单字及字母/符号属于其他单字。组合序列、变体选择符序列和任何多标量文本仍是词组，不做正规化。每个编码中同类的相对顺序保持各格式先验次序（lex 为原 weight 升序、等权稳定）。编码/正常候选集合不变，不补造简码。

令 C/P/R 分别为全表最大同码常用单字/词组/其他单字数，各码三类依次按 1..c、C+1..C+p、C+P+1..C+P+r 赋 weight，再按编码及 weight 排列。因此所有存在类别间均全表严格小于，不仅约束相同完整编码，也涵盖不同码长/任意前缀；缺失类别预留长度为零，仅一类也从 1 开始。同码总候选须 ≤65535，且 C+P+R 须 ≤65535；即使三类极值分属不同编码也相加检查，不可表示时整体拒绝，不回绕、不饱和、不无声合并。策略幂等，已保存结果再次文件导入不变。

低层 `read_lex/write_lex` 仍按原权重忠实往返、严格检查原排序，不夹带该导入策略；`read_wbc3/read_cwb/read_text` 同样保持各自的格式先验顺序。权重不变量不是微软输入法内部候选排序的实机保证，真实前缀显示须用户另行授权安装后人工验收。

## lex

实现依据：<https://github.com/aardio/wubi-lex/blob/master/lib/wubi/lexFile.aardio>（项目 MIT），本项目独立以字节读写实现，未复制 aardio 代码。不视为微软官方规范。

`imscwubi` 八字节魔数；8/10：uint16 版本 1/1；12/16：uint32 索引 0x40、记录 0xA8；20：文件总长；24：0x78563412。索引为 26 个 uint32，含义是各首字母首条记录相对 0xA8 的偏移，空组指向下一组/EOF。头其余字段生成零。

记录：uint16 长度（16 + UTF-16LE 字节数）、weight、编码长度、4 个 uint16 编码字母、UTF-16LE 文本、uint16 零。小 weight 优先。代码/权重升序，等权稳定；所有长度、索引、终止符、填充与代理对核实。当前读取器有意严格限制这一已实现布局；不支持的变体不自动“修复”。

## WBC3

私有格式的受支持子集来自只读研究用户授权样本。header：0x10 总长；0x38 索引起点（0x8C）；0x3C 索引字节数；0x40 条数；0x44 数据起点；0x48/0x4C 数据长度。索引是 count 个相对数据起点的 uint32 偏移，须是完整记录起点的无重复排列，且编码升序。

物理记录：2 字节未知值 + 4 字节未知字段 + 3 字节 LE packed code + uint16 UTF-16LE 文本字节数 + 文本，无额外尾零。packed 低20位由4组5位构成，自高处首个非零开始，1..25表示a..y，不允许中间空洞；高4位未知，不作为码长。索引序而非物理序决定同码候选次序。

样本索引实测为编码字典序、无重复偏移；例如 aaaa 候选索引顺序为“劳斯莱斯、工、恭恭敬敬”，而“工”物理位置更前。未知字段在单字和词组中表现不同，不能宣称是频率或宣称完整无损迁移。导入只保留编码、文本、索引可解释顺序；编码保留简码与全码，不做“出简不出全”过滤。

## 安全

ZIP 不落盘，不以文件名遍历提取；仅选择精确新世纪表，校验目标中央/本地头及可选描述符、store/deflate、CRC与长度。目标外的压缩载荷不解码，故 CRC 只对实际使用的新世纪表验证；目录结构及总声明大小仍检查。拒绝加密、ZIP64、分卷和特殊目标类型。ZIP 解压来自有许可的 puff 2.3，调用互斥保护其初始化。

保存先完成内存编译；原始路径先拒绝设备命名空间、非法字符、ADS 及尾空格/点，再绝对化和词法规范化、检查设备保留名。只在开始时打开盘符根/UNC 共享根，随后以 `NtCreateFile` 的 `OBJECT_ATTRIBUTES.RootDirectory` 逐组件打开并验证普通磁盘目录，最终仍相对已验证的父对象以 `FILE_CREATE`（CREATE_NEW）新建普通磁盘文件。各次名字仅一个组件，使用 `OBJ_DONT_REPARSE`、`FILE_OPEN_REPARSE_POINT`，禁止回退到字符串全路径创建。目录句柄保留身份而非锁住名字/元数据：目录改名/换入另一目录或原地设置 junction 时，操作须拒绝或仍限于已验证对象，不能跟随新指向。系统 API/文件系统不支持时失败，不降低保障；普通相对路径、中文路径和 UNC 语法仍保留，网络文件系统实际行为尚未验证。

完整写入并 flush，失败通过本次新建文件句柄标记删除，避免路径竞态误删已有文件；若清理失败报告 Win32 错误并嵌套保留原错误。`FILE_CREATE` 保证不会覆盖既有目标；此保障不是对抗拥有相同权限者在保存完成后继续修改/移动文件，也不是跨断电事务，断电/进程被杀可能留下半成品。系统部署另由部署模块负责备份与权限。修复依据、验证与内部显式测试观察点见《保存身份修复验证》。

测试采用自有最小断言运行器，无外部测试框架依赖；失败返回非零并由 CTest 收集。构造数据不包含分发的用户词库。真实输入法效果尚需用户授权人工验收。
