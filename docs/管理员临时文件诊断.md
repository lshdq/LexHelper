## 参数、根目录及报告契约

```text
lexhelper_full_security_native_probe.exe --self-test
lexhelper_full_security_native_probe.exe --diagnose --root D:\temp\aiRunner\opencode\LexHelper-admin-fullsecurity-<32hex>
```

`<32hex>` 必须恰好 32 个小写 `[0-9a-f]`；整个路径逐字符匹配上述大小写和反斜杠拼写。只接受 opencode 的**直接子根**，不接受尾斜杠、嵌套路径、点段、ADS、UNC、设备路径、其他盘、其他目录、额外参数。无参数也拒绝，不会回退到 C 盘、TEMP 或当前目录。`--self-test` 不接受 root，不写文件、不启用特权。

诊断根必须由父流程**先前唯一新建**，且满足：

1. D 盘是固定本地 NTFS；从卷根开始所有祖先均为实际普通目录，无 reparse/mount/junction 或不支持属性。
2. 根为空；所有者必须是当前进程用户（内部比较 SID，但不输出 SID）；DACL 必须受继承保护、为已支持 ACE，修改权只允许本用户/SYSTEM/Administrators。父流程应在唯一创建时原子指定此 ACL，而不是修改任意既有目录。跨账户凭据提升会因 owner 不同被拒绝。
3. 父流程保存随机根名、创建证明、源码/EXE SHA；不得取用他人/未知旧根。工具通过 owner、ACL、空目录和 Native 绑定验证对象归属，并不能从一个目录名字证明创建它的历史进程，父流程的创建记录是必要前提。
4. 工具打开祖先/根时不共享写入或删除；存在冲突句柄会安全拒绝，不能为运行成功而放宽 sharing、ACL 或重解析检查。

输出位置固定为 `<root>\diagnostic.log`。由 held root 的 `NtCreateFile(FILE_CREATE)` 唯一创建（等效 CREATE_NEW），根非空/报告已存在即拒绝，不覆盖旧日志。fixture 位于工具新建的 `<root>\fixture-<随机32hex>\fixture.bin`；报告的 `FIXTURE` 行提供相对目录名。父流程只需在**已记录根内**寻找固定日志，不扫描磁盘、不猜新目录。文件内容只是固定公开诊断字串，无私人 CWB。

所有写对象均通过持有目录的 `RootDirectory` 相对创建、确认 `STATUS_SUCCESS`/`IO_STATUS_BLOCK`/`FILE_CREATED`，句柄持有至结束。报告和 fixture 只通过已持句柄 WriteFile/FlushFileBuffers 写入，不用 ofstream/fopen 或字符串重开/rename。后续读查询句柄通过已持 fixture 的**二进制 NTFS file ID**及已持目录 `RootDirectory`、`FILE_OPEN_BY_FILE_ID` 打开，并再次比对 volume/file ID、路径和单硬链接身份；绝不按旧 DOS 文件名重开。持有的创建句柄不共享写/删除。所有句柄、LocalAlloc 描述符及临时 token 都由 RAII 管理。

每次写日志前重新核查各祖先、根及报告对象的实际位置/身份/属性；目录、fixture 和查询句柄也核查对象类型/磁盘/链接数。任何不支持属性或对象置换均拒绝。初始 `D:\` 的打开只读，后续均为 Native 对象相对 I/O。没有覆盖、删除、重命名、ACL 更新或不安全字符串回退。目录失效后不为保存错误而另开路径写日志：已刷盘日志保留，stderr/退出码报告失败；缺 END 一律视为未完成。

## 真实矩阵及 token 生命周期

每个获得的查询句柄比较两个真实 API 的相同 flags：

| flags | 查询 |
|---|---|
| `0x00000007` | Owner/Group/DACL |
| `0x0000001F` | 显式 Owner/Group/DACL/SACL/label |
| `0x00010000` | BACKUP 完整描述符 |
| `0x0001001F` | BACKUP + 显式五项 |

每组记录实际 RequestedAccess、CreateOptions/backup intent、打开 NTSTATUS/Win32；`NtQueryObject` 验证并记录实际 GrantedAccess/返回长度。每个查询记录原样 Win32 或 NTSTATUS/映射 Win32、返回长度、schema 有效性、control。只在成功后检查响应，Native 一次固定 64 KiB 缓冲区；成功长度需在 `[20,65536]` 且通过真实生产 `validate_sd`（偏移、SID/ACL/ACE/重叠等）及自相对/长度/control 校验。两个成功且有效响应另记录 bytes_equal，但不输出任何描述符/SID 内容。

同一实际句柄再执行真实生产 `get_full_security(..., false, "native_probe")`；未注册 simulated_targets/sacls，无 synthetic-success 路由。其成功返回字节再次真实校验，失败保留生产阶段和错误文本。`0x7` 成功绝不被当成完整成功。

15 组依次为：

- 原有效 token：low 句柄；full 句柄 backup intent 关/开。
- 私有线程仅 SeSecurity：full 句柄 intent 关/开；开好 full 后关闭 SeSecurity 再查询。
- 私有线程仅 SeBackup：full 句柄 intent 关/开。
- 私有线程 Security+Backup：intent 关/开；另加已开好句柄后关闭 Security、保留 Backup。
- 私有线程 Security+Restore：intent 关/开；另加已开好句柄后关闭 Security、保留 Restore。
- 私有线程 Security+Backup+Restore：intent 开。

low 请求 `0x00120080`（READ_CONTROL/READ_ATTRIBUTES/SYNCHRONIZE）；full 请求 `0x01120080`（再加 ACCESS_SYSTEM_SECURITY），不请求写入/WRITE_DAC/WRITE_OWNER/DELETE。SeBackup 是否影响结果由实测判断，不预设其为根因。

每个私有组合使用既有生产 `Privileges.enable_names(true,{})` 创建并安装有效 token 的**私有 copy**，然后只对该全新 TokenId 的线程 token 关闭 Security/Backup/Restore，按该组合启用必要权限；`true` 是这个内部权限 scope 的授权门，不是调用应用 system_mode/Deployer。新增禁用逻辑只打开并核验这份私有 token，绝不调整原线程共享 token/进程 token。缺少所需特权只记 `not_available`/`not_verified`；启用失败保留错误，不修改账户策略。

每组记录前、开句柄时、查询时、恢复后的有效 TokenId 及全部 privilege LUID/attributes；前后比较**全部原始 TokenPrivileges 和 TokenId**，并检查进程 token 不变。生产 scope 恢复原线程 token（原本没有则恢复无 token）；恢复失败沿用 fail-fast/TerminateProcess。额外 invariant 在普通返回/异常退出时也校验，无法确认恢复则 fail-fast，绝不让有特权线程正常返回。

## 报告与退出码判读

- UTF-8、CRLF，无 SD/SID/用户名/个人配置；每行 WriteFile 后 FlushFileBuffers。BEGIN/ROW BEGIN/ROW END/SUMMARY/END 分层记录。
- `0`：只表示矩阵尝试完毕、有效/进程 token 恢复检查通过。**不是每项成功，更不是现场修好。** 打开/查询失败和缺权均可出现在退出 0 的完整矩阵内。
- `2`：参数或路径语法拒绝，无对象创建。
- `3`：确认不是已提升管理员，创建/绑定根前拒绝，无标称 privileged 矩阵。
- `4`：环境、根验证、创建/写日志等错误/未完成；报告能安全写时记录 ERROR/END，否则保留已刷盘部分，stderr 报错。恢复失败可能为 fail-fast 异常退出，不是普通 4。
- SUMMARY `matrix_completed` 与 `full_native_success=observed/not_observed` 分离。后者仅表示至少一次有效原生 BACKUP 读取，不证明每组都成功或真实系统对象成功；看 success_count/query_failure_count/not_verified_count 及逐项原始结果。`GetSecurityInfo_denied_Nt_success_count` 只统计确实主 API=5/1314 而相同 flags Native=0 且 SD 校验成功的观察。
- fixture 的真实无审计 SACL/label 状态由 Windows 返回，工具不人为添加审计 ACE/改 ACL。因此即使此矩阵全部成功，也未验证系统对象的特殊 ACE/label 往返。
- 无 END、matrix_completed=0、not_verified、API 错误或 sd_valid=0 都不能记成该项 PASS。工具从不清理现场。

## 微软官方依据（2026-11-18 核验）

- [GetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo)：READ_CONTROL / ACCESS_SYSTEM_SECURITY 的句柄要求；建议打开前启用 SeSecurity、打开后禁用；成功描述符 LocalFree。
- [SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information)：BACKUP 表示全描述符、查询所需 READ_CONTROL+ACCESS_SYSTEM_SECURITY；显式五项不被当成 BACKUP 等价成功。
- [NtQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntquerysecurityobject)：句柄授权、自相对返回、LengthNeeded、NTFS 64 KiB 上限；Native 不绕过对象授权。
- [NtCreateFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile)：RootDirectory、FILE_CREATE/FILE_CREATED、FILE_OPEN_BY_FILE_ID、FILE_OPEN_FOR_BACKUP_INTENT、sharing/reparse 语义。用户态用 Nt 而不是 Zw。
- [DuplicateTokenEx](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-duplicatetokenex)：复制为独立 impersonation token，不修改原 token。
- [AdjustTokenPrivileges](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-adjusttokenprivileges)：不能添加缺失权限；BOOL 成功仍须检查 ERROR_NOT_ALL_ASSIGNED，禁用不是删除。
