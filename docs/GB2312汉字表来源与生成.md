# GB2312 汉字表来源与生成

## 数据定义

生产表 `src/core/gb2312_hanzi.hpp` 只含 GB 2312-80 一级 3755 字和二级 3008 字，共 **6763 个互异汉字**。这里“常用”是本项目的导入策略名称，不是另一套现代通用字规范。

成员依据 GB2312 明确汉字区位：16–55 区为一级（55 区只取 1–89 位，排除末 5 格），56–87 区的 1–94 位为二级。区位对应字节为 `(区+0xA0, 位+0xA0)`，即一级 `B0A1..D7F9`，二级 `D8A1..F7FE`。符号区、未分配格、GBK 扩展区均未枚举。

2026-11-19 使用已安装 PowerShell 7.6.10 / .NET 10.0.15 的显式代码页 936 映射**仅解码以上区位**，异常回退、单 BMP 汉字、去重及两级计数全部检查后生成；没有将 CP936 可编码字符集当作 GB2312。没有下载/复制第三方映射文件或源码；生成器是本项目源码，不增加第三方源码许可证。映射由本机已安装运行时提供，不分发其实现。

## 离线再生成与数据身份

```powershell
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\生成GB2312汉字表.ps1
```

生成器只向标准输出打印完整头文件，不覆盖源码；审核输出后再更新固定表。CMake 不调用该脚本，构建和程序运行不需要 PowerShell/.NET、代码页查询、外部数据或网络。位图覆盖 U+4E00..U+9FFF，328 个 uint64 共 2624 字节；第 n 位表示 U+4E00+n，最低位对应该块最小码点；区间外一律非成员。编译期检查置位数恰为 6763。

数据身份（无 BOM，恰好 6763 个 UTF-16LE 码元，13526 字节）：

| 顺序 | SHA-256 |
| --- | --- |
| 按区、位递增 | `D7F2E477308EBDC62B7805A047D89463CAD21CE69FADF9C92D8E151265191C68` |
| 按 Unicode 码点递增 | `91E406A6F2FD7F217688B296839F84CE425FE1C425D55732ADC1E09DECAE98FC` |

测试不引用生产位图/分类器：使用 Win32 `MultiByteToWideChar(936, MB_ERR_INVALID_CHARS)` 解码同一明确区位，核对 3755/3008/6763 及已知边界（啊、座、亍、齄），再经公共 `import_file` 对整个 U+4E00..U+9FFF 区域的成员和非成员核对精确权重。另以显式模型覆盖 GBK-only 汉字（如丂）、标点/字母、补充平面与多标量序列。此 Win32 查询仅为测试 oracle，生产分类始终使用固定表。
