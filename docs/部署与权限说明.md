## 使用与兼容性边界

- LexHelper 不是微软官方词库编辑器；lex 为逆向格式，不保证官方兼容性。编解码和模拟事务通过不等于真实 Windows 输入法效果已经验收。
- **真实安装/恢复必须在用户点击 GUI 高风险确认后执行。** 导入、预览、另存无需管理员；部署库不替 GUI 征求授权、不自动启动 UAC，调用方须后台执行并完整展示异常。
- `system_mode=true` 必须已提升管理员；目标只能是 `GetSystemWindowsDirectoryW()\InputMethod\CHS`，备份只能是 `SHGetKnownFolderPath(FOLDERID_ProgramData)\LexHelper\Backups`。拒绝任意提权目标和自定义系统备份路径。
- `system_mode=false` 不启用任何特权，禁止 Windows 目录，供临时模拟使用。默认仍要求完整读取安全元数据；普通令牌不能读取审计 SACL 时直接拒绝，不降级为 DACL-only。测试显式注册仅限 D 盘专用目录的虚拟 SACL 后端，见下文。
- Windows 更新、组件修复、输入法词库更新可能覆盖安装结果或使旧备份不适用；不禁用更新、不篡改组件存储/签名。不停止 TrustedInstaller，不终止 ctfmon/输入法/共享文本服务，不安排延迟重启覆盖。成功后提示**注销并重新登录**。
- 本阶段没有读取/修改真实系统 lex 或系统安全属性，也没有执行真实输入法效果、UAC、Windows 更新兼容性验收。使用者应在授权的可恢复 Windows 10/11 x64 测试环境先人工验收，并保有系统级恢复途径。

## 方案决策：保留对象与完整复制的比较

父流程确认当前系统两份 lex 均存在 WinSxS 硬链接，故“拒绝所有目标多硬链接”不能满足需求；也绝不能取消检查后原位写共享 inode。

| 方案 | 取舍 |
| --- | --- |
| 原位写入或改旧对象权限/属性 | 会影响其他硬链接，拒绝 |
| 把旧对象重命名保留，再换入新对象 | 同卷可保留身份，但需要长期保留旁路对象；模拟中观察到旧对象重命名会改变共享 ARCHIVE 属性，故不采用 |
| `ReplaceIfExists=true` 按名字替换 | 减少缺名窗口，但可能覆盖新出现的非预期目录项；不作为本实现的安全退路 |
| **完整元数据复制，精确句柄移除 CHS 链接，随后不覆盖重命名** | 采用。所有正向及回滚副本提前准备；旧对象只移除被固定的 CHS 目录项，不写其数据、owner、DACL、SACL、label 或基本属性。其他硬链接仍指向原实体；恢复内容与权限，不承诺恢复硬链接拓扑身份 |

原件读取后全程持有不共享写入/删除的句柄，直到精确移除该目录项。使用 `FileDispositionInfoEx` 的 POSIX/IGNORE_READONLY 标志后关闭该句柄，**不清除共享原件的 READONLY 属性**。所有新对象都在目标目录同一卷内；备份根可在另一 NTFS 卷。创建/重命名不覆盖既有名字；出现未知对象直接拒绝。

目录项移除与新名放入不是一个文件系统原子动作；双文件操作也不是 ACID 事务。掉电/崩溃可能留下缺少 CHS 文件的中间态和受保护的恢复副本，不宣称绝对恢复。只有 API 可捕获错误适用下述尽力回滚。文件系统会因读取改变 LastAccessTime、因移除硬链接等操作改变 NTFS ChangeTime；不承诺这两个时间或硬链接身份与安装前完全相同，不改系统时钟，也不回写旧共享实体的时间来掩盖这些变化。

## 路径、可信 ACL 与互斥

1. 只接受规范的本地绝对盘符路径；拒绝 UNC、设备路径、相对路径、`.`/`..`、ADS 路径、尾点/空格等歧义；路径保守上限 240 个 UTF-16 单元。
2. 从盘符根锚点逐级以 `NtCreateFile(RootDirectory=已验证父句柄)` 打开目录，检查每级非 reparse/junction。目录句柄固定的是对象而不是名字，不能声称 metadata 句柄省略共享删除就锁住名字。身份、mutex、源文件、目标、备份目录/载荷、暂存及恢复读取均使用同一组目录对象；单组件相对名配合 `OBJ_DONT_REPARSE`、`FILE_OPEN_REPARSE_POINT`，没有按旧字符串重新打开的回退。受控目标/备份要求 NTFS。
3. 安装目标只有 `ChsWubi.lex`、`ChsWubiNew.lex`，它们允许多硬链接，但绝不原位写入；生成输入、备份载荷和新暂存对象仍要求单硬链接。拒绝目录、reparse、额外命名数据流以及压缩/稀疏/加密等未完整支持的属性。输入不能位于目标/备份树。
4. 系统目标目录和原文件必须具有可信 owner/DACL：仅 SYSTEM、Administrators、TrustedInstaller 可修改。系统备份及其应用父目录必须为受继承保护的 SYSTEM/Administrators ACL；模拟备份另允许当前用户。拒绝占坑或普通身份可篡改的备份，不接管、不改宽既有目录 ACL。
5. 新暂存对象使用已验证的完整原安全描述符；系统模式 DACL 与父目录都排除普通用户写入/替换。先后两个文件对象句柄重叠持有，并核对卷/文件 ID；没有放开制品后仅凭字符串重新相信它的空档。新对象的数据写入句柄关闭后改用 metadata-only 句柄提交，避免 NTFS 清理写句柄时再次设置 ARCHIVE；最终属性在新目录项放入后再设置，绝不作用于旧共享对象。
6. 以目标目录卷号/文件 ID 创建 `Global\LexHelper.Deploy.<卷>.<ID>`，所有备份/安装/恢复共享，争用立即拒绝，不无限等待；同时验证锁 owner/DACL，遇 abandoned 状态拒绝自动继续。mutex 只协调本程序，不声称可以暂停 Windows 更新；管理员/SYSTEM 恶意篡改不是隔离目标。
7. 只删除已创建并持有句柄的暂存副本、或已固定的 CHS 目录项；不扫描删除未知 `*.tmp`、历史备份或他人文件。所有旁路名均为 `LexHelper-stage-<128 位随机值>.tmp`，以 Native `FILE_CREATE`（与 `CREATE_NEW` 相同的不覆盖约束）创建。提交/回滚使用 `NtSetInformationFile(FileRenameInformation)`、已验证目标目录 `RootDirectory` 和单组件名，`ReplaceIfExists=false`。目录项身份通过父对象内的相对打开核对，不再靠最终路径文本证明归属。
8. 正常检查点会核对原路径是否仍指向已绑定对象，发现改名或 reparse 状态即拒绝；这些检查只补充及时报错，不充当 TOCTOU 锁。即使检查后发生并发改名，实际 I/O 也不会重新定位到旧名处的 B。可捕获事务错误仍对同一目录对象分别回滚，不因旧名换了 B 就在 B 上补偿。不隔离恶意管理员，也不承诺改名后的诊断路径永远有效。

## 完整安全元数据与最小特权

- 以 `GetSecurityInfo(..., BACKUP_SECURITY_INFORMATION, ...)` 获取完整 self-relative 描述符，不只请求 DACL 或 label 子集。通过 `NtQueryObject(ObjectBasicInformation)` 核对句柄实际拥有 `READ_CONTROL | ACCESS_SYSTEM_SECURITY`，不能把 RequestedAccess 当作 GrantedAccess。仅完整查询返回 5/1314 时，对**同一句柄、同一个 BACKUP 标志**调用一次 `NtQuerySecurityObject`，固定 64 KiB 缓冲、相同严格 schema 验证；不拼接分量查询、不降低完整性。两个 API 都失败时保留首个 Win32 和最终 NTSTATUS/Win32。初次快照/副本准备失败在改 CHS 前拒绝；提交后或回滚时的快照失败按既有事务策略处理，不据路径相同就推断系统从未改变。
- 保存 Owner、Group、DACL、审计 SACL、强制完整性 label，以及 DACL/SACL 的 present、protected、auto-inherited、auto-inherit-request 控制状态。SACL 的缺失、NULL、空 ACL 和含 ACE 状态分别保留；禁止把“没权限读取”解释为“原来不存在”。
- 支持普通 allow/deny DACL ACE、普通 audit SACL ACE、mandatory label ACE。对象/条件/回调/资源属性等其他 ACE 当前明确拒绝，不静默丢弃。label 要求 mandatory authority、单 RID、合法 mask、最多一个 label；SID、ACE/ACL 大小、对齐、控制位、字段重叠均有界验证，之后才调用 Windows 验证/应用 API。
- 新对象通过完整安全描述符创建；必要时只对实际不同的 Owner/Group/DACL/SACL/label 分量使用 `SetSecurityInfo` 及相应保护信息恢复，避免无必要重写 DACL 改变 `0x9004`。每个正向和回滚副本在第一次移除 CHS 链接前，必须已通过全部字节、属性、Owner/DACL/SACL/label 与保护/继承控制位回读比较；操作系统不能按要求保留时拒绝，不放宽比较。
- 普通访问失败后才按原因启用所需权限：`SeSecurityPrivilege` 用于完整审计 SACL 读取/应用；备份读取/删除访问确需时启用 Backup/Restore；恢复不可直接分配的 owner/原权限使用 Restore。只有实际完整性写入失败且目标 label 高于当前令牌时才尝试 `SeRelabelPrivilege`，缺失则在副本准备阶段拒绝。
- 特权只修改从原有效令牌复制出的**私有线程模拟令牌**；不修改进程令牌，不使用 takeown，不永久给 Everyone/Users 加权限。作用域退出恢复原线程令牌（包括原先已有模拟令牌）；无法恢复时 fail-fast，不能把带权限线程还给 GUI。
- `SeSecurityPrivilege` 的关键时点是打开句柄；微软明确说明获得 `ACCESS_SYSTEM_SECURITY` 后可关闭它再读取。不能把 BACKUP 查询失败自动归因为 SeBackup 未启用，也不能在权限不足的旧句柄上启用特权假装补齐访问权。本轮没有增加查询阶段的特权尝试。错误包含 `file_open`/`handle_access`/查询 API/描述符校验阶段、快照调用点、实际 mask、有效线程（无则进程）令牌中三个相关特权的 absent/disabled/enabled 状态，不输出 SID 或描述符。

## 清单 schema v2

每次 `backup()`/`install()` 新建 `backup-<32 位随机十六进制>` 目录并返回；不覆盖历史。`restore()` 先新建当前状态恢复点，成功无返回值，失败异常包含恢复点路径。

| 文件 | 内容 |
| --- | --- |
| `original-0.bin` | 原主词库默认数据流，不携带安装器随附的微软文件 |
| `original-1.bin` | 原 New 默认数据流，仅原来存在时有 |
| `manifest.lhb` | 固定小端二进制，载荷完成后最后写入 |

头为魔数 `LXHB`、版本 **2**、system 模式标记、目标目录卷号与文件 ID；随后原态/预期完成态各两个固定槽，末尾 SHA-256。存在槽含大小、SHA-256、基本属性/四个时间、`FSD2` 完整采集标记、安全描述符长度与完整描述符。记录四个时间不等于保证四个时间保真：新副本会尝试设置这些字段，已有用例支持创建时间、最后写入时间的相应保持；LastAccessTime/ChangeTime 仅作记录与诊断，不作不变承诺。不存在槽只有存在标记。没有来源提供的文件名、输出路径或目标 ACL 路由。

单文件最多 64 MiB，清单最多 1 MiB，单安全描述符最多 64 KiB；精确检查尾部、版本、标记和所有边界。**拒绝旧 v1 自动恢复**，因为它没有完整 SACL/label，不伪装成完整备份升级。哈希是损坏检测，不是数字签名；普通用户防篡改依靠每次验证的备份 ACL，不能对已经取得管理员权限者作防伪承诺。

备份根及新备份子目录若具有压缩、加密等不支持属性，在修改目标前明确拒绝；不会为兼容而自动解压、改宽 ACL 或更改既有目录设置。`FILE_ATTRIBUTE_NORMAL` 不取消 NTFS 压缩继承，不能作为证明。即使目录预检通过，写完也必须使用与 `restore()` **完全相同的 `load_backup/open_regular`** 验证实际清单及全部载荷：属性、单硬链接、无 ADS、可信 owner/DACL、存在性、长度、哈希、v2/FSD2 和目标身份/模式。验证后的文件以不共享写入/删除的句柄保留至本操作结束；`backup()` 返回和安装/恢复首次 unlink 前都不能跳过此门禁。

恢复只接受当前备份根内符合命名的直接子目录，并验证全部载荷与元数据。当前两个槽必须整体匹配该备份原态或预期态（内容、存在性、属性及完整安全元数据），否则拒绝覆盖/删除未知新文件或 Windows 更新后的文件。备份绑定目录身份，不跨机器或重建后的目录直接恢复。

## 提交、回滚及残留

1. 验证非空生成 lex、路径、可信 ACL、锁、两文件及完整安全元数据。
2. 在已绑定备份根对象内新建唯一子目录，写备份载荷，Flush、SHA-256 回读，最后写完整清单；随后通过公共恢复读侧对实际整份材料验证。准备/验证失败时保留未完成备份目录并报路径，尚未改 CHS。
3. 在目标卷准备新主/辅文件和操作前主/辅文件的回滚副本；全部副本都以唯一名字创建，复制完整元数据并回读校验。
4. 只通过原句柄移除 CHS 这一条链接，再以目标目录对象相对、不覆盖重命名放入对应新对象；安装时 New 预期不存在，故不放入新 New。放入后校验父对象内的目录项身份、字节及完整安全状态。
5. 成功时仅清理本次未使用的回滚副本。先将所有这些副本可撤销地标为待删除，全部成功后才关句柄删除；中途异常可撤销先前标记并回滚。
6. 可捕获错误分别回滚两槽；被改动槽只移除本次已知的新对象，放回提前准备的完整副本。未改动槽不写原实体。第一个回滚失败也继续第二个；只有校验过才报告“已回滚”，否则明确“回滚不完整”、目标路径、持久备份及保留恢复副本路径。
7. 正常成功和成功回滚不留旁路文件。清理失败会报出确切制品路径；回滚失败时保留仍需用于恢复的副本，不为“清爽”删除恢复材料。未知同名对象永不覆盖/删除。

数据和安全描述符在副本写句柄关闭前 Flush 并回读；最终属性通过 metadata-only 句柄设置、回读，正常提交保持一致。断电/进程崩溃/存储设备不兑现 Flush/驱动异常均不属于已保证的事务原子性，可能出现缺名或混合状态。此时停止继续安装，保全备份、清单及现场副本，交由有权限的维护人员核对并恢复；常规恢复 API 不猜测覆盖不能识别的部分态。不能仅凭目录存在显示“部署成功”。

## 独立门禁发现的受保护 DACL 缺陷与修复（2026-11-17）

### 问题、原生证据和根因

独立阶段 6 在固定测试 `protected_dacl_roundtrip` 检出两种合法临时文件 DACL 无法正常安装，Debug/Release 都是 12/14 组通过、到达 10222 检查后失败。已只读核对独立报告、日志和两份持久失败样本；其 v2 清单原生控制位均为 **0x9004**，DACL 分别为 `D:P(A;;FA;;;OW)(A;;FA;;;SY)(A;;FA;;;BA)` 与 `D:P(A;;FA;;;WD)`。两份构造 lex 的 SHA-256 均为 `76ACC872CFEAE26238AAF178FE0A6BED71031FFADE9C360B90D2AD7648FB42AE`。未写入或清理这些测试智能体制品。

在修复任务自己的 D 盘普通临时文件上，以原生 Windows API 验证（没有启用权限、没有读取系统安全属性）：

| 合法 DACL | 源控制位 | SetSecurityInfo 重写 DACL | ACE 字节 | 用源 SD 直接 CREATE_NEW | 仅更新 Owner/Group |
| --- | --- | --- | --- | --- | --- |
| OwnerRights + SYSTEM + Administrators | 0x9004 | 0x9404 | 与源完全相同 | 0x9004 | 0x9004 |
| Everyone Full Access | 0x9004 | 0x9404 | 与源完全相同 | 0x9004 | 0x9004 |

`0x0400` 是 `SE_DACL_AUTO_INHERITED`。`SetSecurityInfo` 使用当前自动继承模型；即使 DACL 已 protected，重写它仍可能设置这个模型转换位。旧模拟暂存路径先创建通用 private DACL，再无差别设置 Owner/Group/DACL，因而把合法的旧 protected 描述符 `0x9004` 改成 `0x9404`。严格控制位比较正确地拒绝了结果，并安全回滚；根因不是 OwnerRights ACE 不合法，也不是测试错误。

探针还证实原生 `SetFileSecurityW` 可写回 `0x9004`，但生产修复没有引入按路径覆写安全描述符的兼容性退路，也没有调用不推荐用于文件的 `SetKernelObjectSecurity`。

### 生产方案决策与不变的安全边界

1. 模拟后端只替代 SACL/label。暂存对象创建时直接使用原生 Owner、Group、DACL 及 DACL 控制位；从完整描述符中仅移除由测试后端模拟的 SACL，而不是换成另一套通用 native DACL。真实后端继续用完整源 SD 创建。
2. 后续按真实差异选择 Owner、Group、DACL、SACL/label 各分量，只把需要改动的分量提交给 `SetSecurityInfo`。单独改变模拟 SACL 时不触碰 native DACL，真实 SACL 更新也不无故重写已精确匹配的 DACL。
3. **未修改 `security_equal`，未忽略 protected/AI/AR 等控制位，未弱化回读校验、清单解析、可信目录、路径固定、硬链接或双文件回滚保护。** v2/FSD2 schema 与公开 API 均不变。
4. 修改仅为 `src/deploy/deploy.cpp` 和本说明；`include/lexhelper/deploy.hpp`、核心、GUI、README、根 CMake 和 `.localdoc` 均未改。独立测试代码作为固定门禁保持逐字节不变。
